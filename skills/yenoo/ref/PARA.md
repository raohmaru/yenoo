# PARA Method — Quick Reference

A condensed reference for the PARA Method by Tiago Forte. This document covers the method itself — what PARA is and how to think with it. Implementation details (folder naming, tag systems, migration) are handled by the skill instructions, not here.

## Core Idea

Instead of organizing information by broad subject (like in school — "Math", "History", "Science"), PARA organizes by **actionability** — how close the information is to something you're actively doing or responsible for.

The insight: in your post-academic life, you don't have classes and exams. You have outcomes you're trying to achieve. Your organization should reflect that.

## The Four Categories

### 1. Projects — "What am I working on right now?"

**Definition:** Short-term efforts with a **clear end goal and deadline**. A project has a finish line you can cross.

**Test:** Can you complete this and cross it off? Is there a specific outcome like "done", "shipped", "submitted"? If yes → Project.

**Examples:**
- Write and submit a research paper → done when accepted
- Build an app prototype → done when MVP ships
- Plan a vacation → done when trip is booked
- Pass a mid-term review → done when review is over
- Renovate the bathroom → done when construction finishes

**Every project falls under an area.** "Submit paper to MSSP" (project) belongs to "PhD Research" (area). "Save $5000 emergency fund" (project) belongs to "Personal Finance" (area).

### 2. Areas — "What ongoing responsibilities do I need to maintain?"

**Definition:** Long-term responsibilities with **no end date**. An area has a **standard to maintain**, not a goal to achieve. It continues indefinitely.

**Test:** Does this never truly "finish"? Is there a quality standard you must uphold over time? If yes → Area.

**Examples:**
- PhD Research (ongoing — papers, supervision, lab work)
- Health & Fitness (ongoing — diet, exercise, checkups)
- Personal Finance (ongoing — budgeting, investing, bills)
- Career Development (ongoing — skills, networking, reputation)
- Parenting / Family (ongoing — nurturing, planning, presence)

**Key distinction from Projects:** Projects are sprints — clear goal, intense effort, done. Areas are marathons — sustained performance, no finish line. If you treat an area like a project (e.g., "lose weight" as a one-time effort), you'll revert afterward. If you treat a project like an area (e.g., "writing" with no specific deliverable), it'll feel aimless.

### 3. Resources — "What topics am I interested in?"

**Definition:** Topics or interests you're learning about that **may be useful in the future**. Not tied to a current project or responsibility. Resources are inherently shareable — you could send them to a friend without embarrassment.

**Test:** Is this general knowledge or reference material I'm collecting for interest, not for a specific active commitment? If yes → Resource.

**Examples:**
- Software Engineering (tutorials, best practices, cheatsheets)
- Investment & Finance (book notes, learning paths, strategies)
- Academic Writing (style guides, prompt templates)
- Photography (techniques, gear comparisons)
- Japanese cuisine (recipes, restaurant lists)

**Key distinction from Areas:** Areas are *your responsibilities*. Resources are *topics*. "Personal Finance" (area) = your duty to manage your money well. "Investment & Finance" (resource) = knowledge about how investing works, collectible and shareable. The private vs. shareable test helps: areas are inherently private (your health records, your budget); resources are shareable by default (a tutorial, a booklist).

### 4. Archives — "What's no longer active?"

**Definition:** Inactive items from the other three categories. Completed projects, areas you no longer maintain, resources you've lost interest in.

**Test:** Is this finished, or am I no longer actively maintaining/learning this? If yes → Archive.

**Examples:**
- A completed project (published paper, shipped app)
- Past year's goals and reviews
- A hobby you've stopped pursuing
- A project put on indefinite hold

Archives are not trash — they are "cold storage". The information is preserved and findable, just out of your daily view.

## Decision Flowchart

When any piece of information comes in, ask these questions in order:

1. **Is this something I'm actively working on, with a clear end goal?** → Project
2. **Is this part of an ongoing responsibility I need to maintain?** → Area
3. **Is this a topic I'm interested in or want to reference later?** → Resource
4. **Is it ephemeral, completed or no longer relevant?** → Archive

When in doubt where to put it, ask before placing it. If still not sure put it in the Inbox (sort it during a weekly review).

## Common Mistakes

| Mistake | Why It's Wrong | Fix |
|:--------|:--------------|:----|
| Putting "Marketing" as a project | It never ends — it's an area | Identify the specific *project* within Marketing (e.g., "Launch Q2 campaign") |
| Creating empty folders "just in case" | Creates a labyrinth of empty doors, causes frustration | Only create a folder when you have something to put in it |
| Organizing by topic instead of actionability | A "Psychology" folder mixes your active therapy notes with saved articles from 2 years ago | Split by actionability: active work → Projects, ongoing responsibility → Areas, reference → Resources |
| Having a catch-all "Miscellaneous" folder | Everything ends up there, nothing is findable | Use Inbox temporarily, then sort into PARA during review |
| Never archiving | Old completed projects clutter your view, drain attention | When a project finishes, move its folder to Archives immediately |

## The "Never Create Empty Folders" Rule

One of the most counterintuitive PARA principles: don't pre-create folders you *might* need. Only create a folder the moment you have something to put in it. Pre-created empty folders look organized but cause frustration — every click into an empty folder is a broken promise. It takes only a moment to create a folder when you actually need one.

## The Weekly Review

PARA is not a "set it up once and forget it" system. It works because of a simple maintenance habit:

1. **Review your Projects** — are they still active? Any to archive?
2. **Check your Inbox** — sort anything unsorted into the right category
3. **Reflect on Areas** — anything being neglected?
